Pi Agent: from prompt to Tool Result

A reading edition of the source Markdown. Read before testing; see answers only after submission.

Learning outcome: explain the complete loop from “list files on my desktop” to a model’s final answer.

1. A correct mental model

Pi does not understand a natural-language request or automatically run ls. It is an Agent Harness / Runtime. The model reasons and decides; Pi assembles context, dispatches tools, persists the session, and renders events.

The model thinks. Tools connect to the external world. The runtime makes the loop controlled, observable, and recoverable.

2. The complete request lifecycle

User: “List desktop files”
→ Pi TUI receives input
→ AgentSession assembles rules, history, and schemas
→ LLM decides it needs a real observation
→ Tool Call requests bash / find / read
→ Tool Runtime dispatches a tool
→ Shell / filesystem returns stdout, stderr, or an error
→ Tool Result enters the Session and model context
→ LLM gives a grounded final answer

A tool task normally requires two model calls: one to choose a tool and one to interpret the observed result.

3. Who thinks and who acts?

ComponentRole
Pi TUIReceives input and renders events; does not decide commands.
AgentSessionOwns session, queues, tool set, persistence, retries, and compaction.
LLMInterprets intent, chooses tools, reads results, and answers.
Tool RuntimeFinds implementations, passes arguments and AbortSignal, wraps results.
Shell / filesystemPerforms real operations; knows neither intent nor context.
Session JSONLKeeps a durable trace for recovery, replay, and audit.

4. Tool Call: the model requests action

{
  "id": "call_01",
  "name": "bash",
  "arguments": { "command": "find ~/Desktop -maxdepth 1 -type f" }
}

A Tool Schema is the model-visible contract: name, description, and parameter structure. It is not the implementation that executes a command.

5. Tool Result: the runtime returns facts

{
  "toolCallId": "call_01",
  "toolName": "bash",
  "isError": false,
  "content": [{ "type": "text", "text": "...desktop files..." }]
}

Tool Results are an Agent’s sensory input. The model observes files, tests, web pages, databases, and APIs through results; it does not receive direct OS permissions.

6. Session is the durable trace

Pi persists a JSONL trail containing user messages, assistant messages, Tool Calls, Tool Results, model changes, and summaries. This supports recovery, branching, export, replay, and audit.

7. Cancellation and output limits

Escape starts an abort. The runtime propagates an AbortSignal to tools, and a bash tool should stop the shell and its process tree. Stopping only the UI is not correct cancellation. Large outputs should be bounded, retained by reference, and inspected with narrower follow-up queries.

8. A prompt is not a security boundary

Models can misunderstand or be prompt-injected. Enforce security in Tool, Runtime, and OS layers: allowlists, path validation, least privilege, approval, containers, or remote sandboxes.
