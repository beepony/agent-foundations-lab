THE THESIS

模型之外，仍有一套确定性系统

LLM 负责判断与规划；Runtime 负责让它观察、行动、取消、恢复和留下可审计的轨迹。

Agent 不等于
“模型 + Prompt”
一个可靠的 Agent，必须把不确定的模型放进有工具边界、状态机、日志和安全策略的运行环境。

Pi 是这个思想的具体例子：TUI、Session、工具、模型连接和扩展各自分工，通过事件和消息协作。

RESPONSIBILITY BOUNDARIES

谁在思考？谁在行动？

点击组件，理解它的输入、输出和边界。把这些职责混在一起，是 Agent 设计中最常见的误解。

DATA CONTRACTS

模型请求动作；Runtime 返回事实

Tool Call 与 Tool Result 用同一个调用 ID 关联。模型只看见 Tool Result，不会直接触碰你的文件系统。

TOOL CALL · FROM LLM

{
  "id": "call_01",
  "name": "bash",
  "arguments": {
    "command": "find ~/Desktop -maxdepth 1 -type f"
  }
}

TOOL RESULT · FROM RUNTIME

{
  "toolCallId": "call_01",
  "toolName": "bash",
  "isError": false,
  "content": [{ "type": "text", "text": "...files..." }]
}
